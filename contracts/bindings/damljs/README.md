# @chainlink/canton-contracts

Official TypeScript bindings for the [Chainlink Canton contracts](https://github.com/smartcontractkit/chainlink-canton), generated with `dpm codegen-js` from the released DARs in [`contracts/dars/released`](../../dars/released).

The package is published to npm automatically on `contracts/vX.Y.Z` releases (see [Publishing](#publishing)).

## Publishing

Publishing runs on every `contracts/vX.Y.Z` tag in the [`release-publish` workflow](../../../.github/workflows/release-publish.yaml), gated by the `NPM_PUBLISH_ENABLED` repository variable. It uses npm trusted publishing (OIDC) via the `publish` GitHub environment — no long-lived npm token is stored.

Activation checklist:

1. Configure npm trusted publishing for `@chainlink/canton-contracts` (workflow `release-publish.yaml`, job `publish-npm-bindings`, environment `publish`).
2. Ensure the `publish` GitHub environment exists in this repository.
3. Set the `NPM_PUBLISH_ENABLED` repository variable to `true`.

## Installation

```bash
npm install @chainlink/canton-contracts
```

## Usage

The package contains one directory per Daml package, named `<package>-<package version>`. Import the bindings for a Daml package as a deep import:

```ts
import { CCIP } from '@chainlink/canton-contracts/ccip-api-v2-2.0.0';
```

or in CommonJS:

```js
const { CCIP } = require('@chainlink/canton-contracts/ccip-api-v2-2.0.0');
```

A convenience barrel re-exporting every package is available at the package root:

```js
const bindings = require('@chainlink/canton-contracts');
bindings['ccip-api-v2-2.0.0'].packageId;
```

Cross-package references inside the generated bindings (e.g. the `ccip-api-v2` bindings referring to `splice-api-token-metadata-v1`) resolve to deep imports of this package, so no additional packages need to be installed.

### Peer dependencies

The generated bindings require [`@daml/types`](https://www.npmjs.com/package/@daml/types) as a peer dependency, pinned to the major/minor of the Daml SDK the bindings were generated from. Install a matching version alongside the bindings.

## Versioning

The package version tracks the `contracts/vX.X.X` releases of the [`chainlink-canton` repository](https://github.com/smartcontractkit/chainlink-canton): bindings vX.Y.Z are generated from the DARs of contracts release vX.Y.Z. See the repository's [contracts CHANGELOG](../../CHANGELOG.md) for what changed.

The release-please release PR for `contracts` automatically bumps `version` in this package's `package.json` (via the
`extra-files` JSON updater in [release-please-config.json](../../../release-please-config.json)), so the committed
version always matches the release the bindings were regenerated from.

Multiple deployed versions of the same Daml package lineage (e.g. `ccip-burn-mint-token-pool-v2-2.0.0` and `ccip-burn-mint-token-pool-v2-2.1.2`) are included side by side; import the one matching the deployed contract.

## Regeneration

The bindings are generated by [`contracts/cmd/genbindingsjs`](../../cmd/genbindingsjs) and committed so changes are reviewable. To regenerate after releasing new DARs:

```bash
make generate-bindings-js
```

Requires `dpm` and Go. CI fails if the committed bindings drift from the released DARs.
